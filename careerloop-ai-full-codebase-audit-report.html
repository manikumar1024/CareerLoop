6. CURRENT USER FLOW

New User Flow

  1. Lands on / — sees real-time metrics (or "—" if empty DB) + role hub cards
  2. Clicks role CTA or SIGN IN → /signin?role=TRAINEE
  3. Either: (a) clicks "Quick Demo Access" seeded user, or (b) selects role + enters email/password
  4. If no account exists: auto-created in DB by NextAuth credentials provider
  5. Redirected to role dashboard; if no profile exists → shown EmptyState with "Setup Profile" → /onboarding
  6. Onboarding: selects role, provides district/org name → POST /api/onboarding → creates TraineeProfile/EmployerProfile/etc.
  7. Redirected to role dashboard with initialized profile

Returning User Flow

  1. Lands on /, session active → Navbar shows "[ROLE] DASHBOARD" link
  2. Clicks dashboard → role layout applies sidebar + protects with getCurrentUser() auth check
  3. If session expired: redirected to /signin?callbackUrl=…

8. WHAT EXISTS vs. WHAT IS MISSING

Fully Implemented ✅

  • End-to-end trainee lifecycle: profile → skills → training → certification → jobs → employment → follow-ups
  • Employer verification queue with server actions (verify/reject)
  • Job posting, skill requirements, trainee application with match scoring
  • 30/90/180/365-day longitudinal follow-up engine
  • AI skill gap analysis with deterministic fallback
  • AI career coach (next-best-action engine)
  • Government admin macro analytics: retention curves, wage progression, district rankings, non-placement pie
  • CSV export for GOVERNMENT_ADMIN
  • Consent management (grant/revoke) + full audit log
  • Non-placement root cause tracking
  • SkillEvidence system with confidence levels
  • Career timeline page (full chronological with year grouping)
  • Certification wallet with 6-step verification status
  • External profile linking (GitHub, LinkedIn, LeetCode, etc.) — UI exists in identity page
  • Self-employment ventures recording
  • Apprenticeship record tracking
  • Real-time analytics from DB (no fake data guards throughout)

Gaps / Missing or Incomplete 🔴

  • Quick Demo Access panel — must be removed for production; contains hardcoded seed emails/password
  • NEXTAUTH_SECRET hardcoded fallback — must be env-only; current fallback is predictable
  • Admin authorization code fallback — "CAREERLOOP-GOV-ADMIN" is in source code; must be env-only
  • ApprenticeshipRecord UI — no add-apprenticeship form exists (only display in outcomes page if records already exist in DB); trainee cannot self-report apprenticeship through UI
  • Trainee outcomes page — has self-employment form but NO apprenticeship add form
  • External profile GitHub/LinkedIn sync — UI exists for input/display; actual OAuth token sync / API fetching NOT implemented (rawData is cached but no sync endpoint)
  • Provider portal depth — programs page exists but batch enrollment, assessment logging, and certification issuance from provider side not audited in depth
  • Admin skills page — full skill taxonomy management (UI exists) but skill addition from admin not confirmed working
  • Password reset / forgot password — not implemented
  • Email notifications — follow-up scheduling, milestone alerts — no email provider configured
  • Employer candidates page — exists but not deeply audited
  • Policy Recommendation DB model — exists in schema but no CRUD UI to save/manage persistent recommendations; only in-memory synthesized on demand
  • AIInsight model — defined in schema but never written to in any code path (unused)
  • CompensationHistory model — defined but never written to; no wage history tracking page
  • Trainee date-of-birth / gender — fields in DB but no collection UI (only district, phone, education in profile form)
  • Seed file (prisma/seed.js) — referenced in package.json scripts but not audited; assumed to contain the demo accounts
